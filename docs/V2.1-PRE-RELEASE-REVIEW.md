# Pi.js 2.1 Pre-Release Review

## Outcome

Pi.js 2.1 is not release-ready yet. The core implementation looks solid and all 34 existing
visual tests pass, but the review found two release-blocking issues, two moderate
resource/lifecycle defects, and two cleanup items.

The review covered only core changes between `v2.0.3` and `main`. Pi Vision, unrelated demos,
generated 2.0.3 release artifacts, and unchanged legacy code were excluded.

## Findings

### FIXED - P1: Invalid custom shaders can permanently stop automatic rendering

`setImageDirty()` in `src/renderer/renderer.js` sets `isRenderScheduled` before flushing. If
shader compilation, linking, or the `u_texture` check throws, execution never resets that flag.
The failing shader also remains in `drawOrder`, so later flushes retry it and later drawing does
not schedule another render.

Recommended correction:

- Validate or compile a shader synchronously when it is first applied to a screen, or make batch
  flushing transactional.
- Always reset scheduling state in a `finally` block.
- Discard or quarantine the failing shader item so future flushes can continue.

Relevant locations:

- `src/renderer/renderer.js:303-320`
- `src/renderer/batches.js:452-456`
- `src/renderer/batches.js:559-623`

### FIXED - P1: Published TypeScript declarations will be incorrect and stale

The 2.1 metadata correctly states that `createShader()` returns `number`, coordinate conversion
functions return `PositionPx`, and `width()` and `height()` return `number`. However,
`docs/llms/pi.d.ts` declares these functions as returning `void`, and its `screen()` overload
omits the new `parent` parameter.

The metadata generator converts `returns` into an object, but later reads it as an array. Every
generated method consequently falls back to `void`. The release instructions also build and copy
artifacts without regenerating metadata, so `build/pi.d.ts` can be stale when copied into the npm
package.

Recommended correction:

- Read `method.returns.type` and `method.returns.description` consistently in the generator.
- Make the build or release-copy workflow regenerate metadata before packaging.
- Regenerate and verify both `build/pi.d.ts` and `docs/llms/pi.d.ts`.
- Add a release assertion for the 2.1 return types and the `screen({ parent })` overload.

Relevant locations:

- `scripts/generate-metadata.js:67-80`
- `scripts/generate-metadata.js:166-170`
- `scripts/generate-metadata.js:258-260`
- `docs/llms/pi.d.ts:1031`
- `docs/llms/pi.d.ts:1280-1281`
- `docs/llms/pi.d.ts:1503-1523`
- `docs/llms/pi.d.ts:1840-1841`
- `releases/publish.md:4-5`
- `scripts/copy-to-release.js:28-45`

### FIXED - P2: `removeImage()` can delete a texture referenced by a queued draw

`removeImage()` immediately calls `deleteTexture()`. Unlike texture updates, deletion does not
first check `textureBatchSet` and flush pending users. The following sequence can therefore delete
the texture before the scheduled batch renders:

```javascript
$.drawImage( "ship", 0, 0 );
$.removeImage( "ship" );
```

Recommended correction: put the safety check inside `deleteWebGL2Texture()`. Flush the screen if
the texture is present in `batchInfo.textureBatchSet`, then delete it.

Relevant locations:

- `src/api/images.js:261-279`
- `src/renderer/textures.js:259-278`

### FIXED - P2: Invalid fragment shaders leak a successfully compiled vertex shader

`createShaderProgram()` compiles both stages. When the built-in vertex shader succeeds and the
custom fragment shader fails, the function throws before deleting the successful vertex shader.
Repeated failures can therefore accumulate WebGL shader resources.

Recommended correction: delete whichever stage compiled successfully before throwing,
preferably through a `try`/`finally` cleanup structure.

Relevant location: `src/renderer/shaders.js:65-89`.

### FIXED - P3: The main README identifies 2.0.0 as the latest version

`README.md:60` says the latest version is 2.0.0 even though the package and changelog are prepared
for 2.1.0.

Recommended correction: update the current-version text before release.

### FIXED - P3: One changed line violates the whitespace gate

`src/core/screen-manager.js:308` contains trailing whitespace. This is the only failure reported
by `git diff --check` for the reviewed 2.1 files.

## Validation Results

- Build passed through `node scripts/build.js`.
  - Full and lite builds succeeded.
  - ESM and IIFE outputs succeeded in minified and unminified forms.
  - Version injection reported `2.1.0`.
- Existing Chromium visual suite passed: **34 of 34 tests**.
- `git diff --check` found only the trailing whitespace described above.
- No source files or approved visual baselines were changed during the review.

The host's user-level `npm` launcher was broken, so the same repository scripts were invoked
directly with Node. This was an environment issue rather than a Pi.js build failure.

## Residual Risks and Coverage Gaps

- Invalid shader recovery is not covered by the existing fixtures.
- Drawing an image and immediately removing it is not covered.
- Generated declarations are not automatically validated against metadata or runtime returns.
- The suite does not make explicit GPU memory assertions.
- The existing automated visual suite targets Chromium only.

## Optional Follow-Up Feature Ideas

These ideas are advisory and should not expand the 2.1 release scope.

Feature idea 6, expanded uniform types and texture inputs, was promoted into 2.1 and implemented
with reflected numeric, boolean, matrix, uniform-array, and `sampler2D` image inputs.

| Rank | Idea | Likely API | Risk | Suggested fit |
| ---: | --- | --- | --- | --- |
| 1 | Shader disposal and diagnostics | `removeShader()`, `getShaderInfo()` | Low-medium | 2.2 minor |
| 2 | View-aware pointer conversion | `pointerToView()`, `isPointInView()` | Low | 2.2 minor |
| 3 | Scoped view helper that always pops | `withView(rect, callback)` | Low | 2.2 minor |
| 4 | GPU-native view capture | `createImageFromView()` or `captureView()` | Medium | 2.2 minor |
| 5 | Reusable shader pipelines | `createShaderPipeline()`, `applyShaderPipeline()` | Medium | Later minor |
| 7 | Built-in post-processing presets | Optional CRT, palette, scanline, and bloom plugin | Low-medium | Standalone plugin |

The remaining feature ideas stay advisory and are not part of the 2.1 release.
